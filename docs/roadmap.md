# Roadmap

Each phase ends with a working, tested increment. Commits are made manually by the maintainer.

| # | Phase | Acceptance criteria | Status |
| --- | --- | --- | --- |
| 0 | Inspection & architecture | Stack chosen and justified; Vercel/external boundary documented | Done |
| 1a | **Foundation** | Next 16 + strict TS + Tailwind; validated env; Drizzle schema + migrations; Better Auth email/password; RBAC (`user_role`) with server-side checks; append-only audit log; PGlite-backed integration tests; lint, typecheck, test and build all green | Done |
| 1b | Seed & admin bootstrap on Neon | Migrations applied to a Neon dev branch; `grant-role` bootstrap; idempotent `npm run seed` for demo setter/reviewer/contestant + a published demo contest; `/api/health` ok against Neon | Done |
| 2a | Contests & problems | Setters/admins create problems (statement, limits, difficulty, tags, private template notes, examples, hidden tests ≤ 256 KB/field, reference solution) and contests (window, problem set, publish). Ownership-scoped authz (setters manage only their own; admins all). Publish requires ≥ 1 problem, each with tests + reference solution, and a future start. Problem set and start time lock once running. Contestants see published contests, problems only after start, and statements that never include hidden data; registration is idempotent and closes at the end. All mutations audited | Done |
| 2b | Submissions & judge | `JudgeProvider` interface with a deterministic **mock judge** (never executes code); CodeMirror 6 editor (C++17) with drafts, example runs and submissions; immutable snapshots (DB trigger + SHA-256 CHECK); `judge_job` queue with leases, fencing, retries/backoff and dead-lettering; queued → running → verdict; per-user throttles; history, submission detail and ICPC standings. Tests cover transitions, lease expiry, immutability, access, and that contestants never receive hidden tests | Done |
| 3 | Instrumented IDE + telemetry | Versioned notice (`lib/telemetry/notice.ts`) that must be accepted at registration (append-only acknowledgement rows; editor and submissions blocked until the current version is accepted); persistent recording indicator; CodeMirror transactions classified by userEvent (typed/paste/drop/complete/delete/undo/redo) with sizes only; focus, visibility, heartbeat, run/submit markers; periodic + pre-submit snapshots; versioned Zod schema; batches with session id + seq, localStorage outbox, keepalive on unload, backoff; idempotent ingest (`(session_id, seq)` PK, ON CONFLICT DO NOTHING) with arrival order; submissions linked to session + seq; reviewer-only timeline with data-quality warnings (missing seqs, out-of-order, gaps, skew, snapshot/submission mismatch); 180-day retention cron | Done |
| 4 | Features + baseline scorer | Personal templates (append-only versions, frozen at contest start) and approved per-contest snippets; token-shingle template coverage; deterministic `features-v1` with availability + explanations; data-quality coverage → "insufficient data" instead of a score; transparent `baseline-v1` (documented priors, robust-z cohort mode with absolute floor); append-only feature vectors (input digest) and assessments (reference digest); durable `analysis_job` queue triggered by judging, contest-end re-scoring cron; reviewer-only queue/detail API. See docs/integrity.md | Done |
| 5 | Reviewer dashboard | Review cases (auto-opened for the first elevated assessment, or manually; one active case per subject); queue with contest/problem/contestant/status/band/score filters and pagination; case page with data-quality warnings first, per-signal score breakdown, templates in effect, doc-length chart, notable-event timeline with gaps, snapshot/submission diffs, submissions; append-only decisions (no concern / inconclusive / confirmed violation, ≥ 30-char rationale), notes, reopen; two-person rule (different admin confirms; DB trigger); separation of duties (own work / own contest); confirmed violations exclude the problem in standings; neutral contestant notice + written responses; admin audit log page | Done |
| 6 | Evaluation | Seeded TypeScript generator (`eval/`) runs the production extractor and scorer over 15 clearly labelled synthetic scenarios (incl. hard negatives and designed misses) with random telemetry degradation; Python `ml/` (scikit-learn, pinned venv) compares baseline priors/cohort, Isolation Forest (unlabelled and clean) and logistic regression with contestant-grouped CV, PR-AUC, precision/recall/F1/FPR, per-scenario rates, workload, threshold sweep and cluster-bootstrap CIs; generated `docs/evaluation.md` with failure analysis and limitations; reproducible byte-for-byte | Done |
| 7 | Security & reliability | External judge on an isolated VM (CPU/mem/wall/pids/fs/network limits, no secrets, signed callbacks); rate limits; retention policy for telemetry; Vercel deploy verified | |
| 8 | Polish & portfolio | UI polish, accessibility pass, demo script, README walkthrough, screenshots | |
